# SPASIBA — 주차장 차량 위치 안내 시스템

지하주차장 복도에 설치한 카메라가 **주차된 차의 번호판을 읽어 주차 위치를 기록**하고, 결제 키오스크나 앱에서 **내 차까지 가는 최단 경로**를 안내합니다.

- 카메라: 라즈베리파이 4 + Pi 카메라 / 로지텍 웹캠
- 데모: 우드락으로 만든 모형 주차장 + 모형 차 + 확대 출력한 번호판

---

## 1. 동작 방식

```
[Pi]   카메라 → ① 번호판 검출 → ② 줄 검출 → ③ 줄별 글자 인식 → ④ 위→아래로 이어 붙이기 → 글자별 확률표 + 주차칸(slot_id) 전송
[서버] ⑤ 버퍼 매칭: 입차했지만 아직 주차 위치가 없는 차량 후보와 비교
          └ 애매하면 Pi에 번호판 crop 재요청 → ⑥ 2차 판독
       → 확정: DB에 주차칸·번호 저장
       → 실패: "미확인 차량"으로 저장, 사용자가 사진으로 확인
```

| 단계 | 하는 일 | 방법 | 상태 |
|---|---|---|---|
| ① 번호판 검출 | 카메라 화면에서 번호판 영역을 박스 하나로 잘라냄 | YOLO11n (`plate_v3`) | ✅ 완료 |
| ② 줄 검출 | 번호판 crop 안에서 글자 줄을 찾음 (1줄 또는 2줄) | PP-OCR det | ✅ 시험 완료 |
| ③ 글자 인식 | 줄마다 글자를 읽고 글자별 확률을 냄 | CTC 기반 인식 모델 | 🔜 다음 단계 |
| ④ 이어 붙이기 | 줄이 여러 개면 위→아래 순서로 합쳐 번호 하나로 | 규칙 | 🔜 |
| ⑤ 버퍼 매칭 | 입차 기록과 비교해 번호 확정 | 서버 | 계획 |
| ⑥ 2차 판독 | 애매한 경우 서버에서 다시 읽기 | AI Hub CRAFT + STR | 계획 |

### 설계에서 정한 것

- **번호판을 먼저 찾고, 그 안에서만 읽습니다.** 차 로고·모델명, 간판, 택시 표시등 같은 다른 글자를 읽지 않기 위해서입니다.
- **한 줄/두 줄을 따로 판단하지 않습니다.** 검출기가 잘라준 crop 안의 글자는 전부 한 번호판입니다. 줄이 2개면 위→아래로 이어 붙입니다 (초록 구형·노란 영업용·화물차 번호판).
- **③은 CTC 기반이어야 합니다.** 서버의 버퍼 매칭이 글자별 확률표를 씁니다.
- **영업용(지역명) 번호판을 포함합니다.** 지역명 17개는 토큰 하나씩으로 다룹니다 (`서울`, `경기` …).
- **이륜차·건설기계·외교 번호판은 대상에서 제외**하고, 운영에서는 "미확인 차량"으로 처리합니다.
- **라즈베리파이에서 직접 돌립니다.** 외부 API는 느리고 부담스러워서, 작은 모델을 직접 학습합니다.

## 2. 저장소 구성

| 폴더 | 내용 |
|---|---|
| [`detector/`](detector/) | ① 번호판 검출기. 학습된 가중치 `weights/plate_v3.pt`, 데이터 준비·평가 스크립트. **사용법은 [`detector/README.md`](detector/README.md)** |
| [`ocr/`](ocr/) | OCR 데이터 분석(`analyze_data.py`), PP-OCR 줄 검출 시험(`test_line_det.py`) |
| [`docs/`](docs/) | 실험 기록. [`plate_detector_v2.md`](docs/plate_detector_v2.md): 검출기 v1 실패 원인부터 v2·v3 데이터, 결과까지 |

### 번호판 검출기 현황 (`plate_v3`)

| 평가 | 결과 |
|---|---|
| 검증 세트 Recall (출처별) | 거리 CCTV 0.969 / 주차장 흑백 0.960 / 블랙박스 0.833 / 야간 1.000 |
| 웹에서 모은 실제 사진 21장 | 21장 모두 번호판 검출 |
| 초록 구형 번호판 26장 (폭 30px 이상 30개) | 30 / 30 |

알려진 한계: 초록 번호판 박스가 다소 넉넉함, 폭 30px 미만의 아주 작은 번호판은 놓침, 실제 지하주차장·데모 환경 평가는 아직 하지 않음.

## 3. 데이터

데이터는 **저장소에 올리지 않습니다.** 서버의 `~/sooin/spasiba/data/`에 있습니다.

| 데이터 | 쓰임 | 비고 |
|---|---|---|
| AI Hub "자동차 차종/연식/번호판 인식용 데이터" — OCR crop 9만 장 | ③ 글자 인식 학습, ① 두 줄·초록 번호판 보강 | 번호 글자 라벨만 있고 박스는 없음 |
| AI Hub 같은 데이터 — 원본 CCTV 프레임 | 사용 안 함 | 번호판이 전부 블러 처리됨 |
| Roboflow Universe 차량·번호판 데이터 4종 | ① 검출기 학습 | 차 + 선명한 번호판. 출처는 `detector/download_rf.py` |
| 웹에서 모은 실제 사진 (21장, 초록 번호판 26장) | 평가 전용 | 학습에 절대 넣지 않음 |

## 4. 환경

| 항목 | 값 |
|---|---|
| 학습 서버 | Ubuntu, RTX 4090 (24GB) |
| 주요 패키지 | Python 3.10, torch 2.11 (CUDA 12.8), ultralytics 8.4, paddlepaddle 3.x / paddleocr 3.x, opencv-python-headless |
| 실행 장비 | 라즈베리파이 4 (예정: YOLO는 NCNN으로 변환) |

```bash
python -m venv venv && source venv/bin/activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install ultralytics opencv-python-headless paddlepaddle paddleocr
```

PaddleOCR를 CPU에서 돌릴 때는 `enable_mkldnn=False`가 필요합니다 (oneDNN 버그).

## 6. 주의 사항

- **선명한 번호판은 개인정보입니다.** 데이터와 번호판이 보이는 결과 그림은 커밋하지 않고(`.gitignore` 참고), 외부 라벨링 서비스에 올리지 않습니다. 발표 자료에서는 번호판을 가립니다.
- AI Hub 데이터는 이용 조건(학습·연구 목적, 재배포 금지) 안에서 씁니다. Roboflow 데이터는 각 데이터셋 페이지의 라이선스를 따릅니다.
- 가중치는 최종 모델(`detector/weights/plate_v3.pt`)만 저장소에 올립니다.
