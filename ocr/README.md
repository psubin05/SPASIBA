# ocr — 번호판 글자 읽기

SPASIBA 파이프라인의 **② 줄 검출 → ③ 글자 인식 → ④ 이어 붙이기** 단계입니다. [`detector`](../detector/)가 잘라준 번호판 crop을 받아 번호와 글자별 확률을 냅니다.

```
[Pi] 카메라 → ① 번호판 검출 → ② 줄 검출 (여기) → ③ 글자 인식 (여기) → ④ 이어 붙이기 (여기) → 서버
```

| 항목 | 값 |
|---|---|
| 기본 모델 | **`weights/ocr_v1.pt`** (CNN + BiGRU + CTC, 147만 파라미터, 5.7MB) |
| 입력 | 번호판 crop. 두 줄이면 윗줄·아랫줄을 좌우로 펴서 한 번에 읽음 |
| 출력 | 번호(`서울12가3456`), 전체 확신도, 글자별 상위 3개 후보와 확률 (서버 버퍼 매칭용) |
| 학습 데이터 | AI Hub OCR crop 55,000장 (plate_v3로 잘라 실제 파이프라인과 같은 조건) |
| 성능 | AI Hub 테스트 7,030장 **전체 일치 96.0%** |

## 1. 바로 써보기

```bash
source ~/sooin/spasiba/venv/bin/activate
cd ~/sooin/spasiba/SPASIBA/ocr
python plate_reader.py <사진 폴더> --out read_out     # 결과 그림(박스 + 번호) + results.csv
```

```python
from plate_reader import PlateReader

reader = PlateReader()                 # ① detector/weights/plate_v3.pt + ③ weights/ocr_v1.pt
for p in reader(image):                # image: BGR numpy (cv2)
    p["text"]        # '서울12가3456'
    p["conf"]        # 전체 확신도 (글자 확률의 곱). 0.3 미만이면 틀렸을 가능성이 큼
    p["box"]         # 번호판 위치 (x1, y1, x2, y2)
    p["n_lines"]     # ②에서 찾은 줄 수
    p["char_probs"]  # [[('서울', 0.98), ('경기', 0.01), ...], ...] 글자마다 상위 3개
```

## 2. 동작 방식

1. **① 검출**: `plate_v3`로 번호판 박스를 찾고 사방 4% 여백을 두고 자른다.
2. **② 줄 검출**: PP-OCRv5 mobile det으로 글자 영역을 찾고, 로고·작은 글씨는 가장 큰 글자를 기준으로 걸러 줄을 나눈다.
3. **펴기**: 줄이 2개면 윗줄과 아랫줄을 같은 높이로 맞춰 **좌우로 이어 붙인다** (`경기71` + `아3595` → 한 줄 이미지). 1줄이면 crop을 그대로 쓴다.
   **한 줄/두 줄을 따로 판단하는 단계는 없다.** crop 안의 글자는 전부 한 번호판이다.
4. **③ 인식**: 높이 48 × 폭 256으로 맞춰 CNN + BiGRU + CTC로 읽는다. 지역명 17개(`서울`, `경기` …)는 토큰 하나씩이다.

펴기를 쓰는 이유: AI Hub 라벨은 번호 전체(`서울4도9472`) 하나뿐이라 줄별 정답이 없다. 펴면 라벨을 그대로 쓸 수 있고, Pi에서 번호판 하나당 인식을 한 번만 돌리면 된다.

## 3. 성능

### AI Hub 테스트 (학습에 쓰지 않은 번호 7,030장)

| 종류 | 장수 | 전체 일치 | 글자 오류율 |
|---|---|---|---|
| **전체** | 7,030 | **96.0%** | 1.0% |
| 일반 한 줄 (`12가3456`) | 5,488 | 96.2% | 0.9% |
| 지역명 한 줄 (`서울31자1234`) | 1,023 | 96.7% | 1.2% |
| 지역명 두 줄 (노란 영업용 `경기71 아3595`) | 471 | 94.1% | 1.4% |
| 일반 두 줄 (초록 구형 `02마 3502`) | 48 | 75.0% | 3.5% |

같은 글자가 연속된 번호(`5555`, `8830`)도 95.6%로 차이가 없다.

### 웹에서 모은 실제 사진 (정답 라벨 없이 눈으로 확인)

- 크고 선명한 번호판은 대부분 맞는다.
- 작거나 흐린 번호판, **초록 구형 두 줄 번호판**(특히 지역명이 있는 `서울56 나7804`)은 자주 틀린다. AI Hub 학습 데이터에 이 종류가 거의 없다.
- 틀린 결과는 대부분 확신도가 0.3 미만이다 → 서버에서 재요청·2차 판독 기준으로 쓸 수 있다.

**데모에서 두 줄 번호판을 보여줄 때는 노란 두 줄(택시형)을 권장**한다 (94.1%).

## 4. 처음부터 다시 만들기

```bash
python make_ocr_v1.py                 # AI Hub OCR crop → data/ocr_v1/ (약 15분, tmux 권장)
python train_ocr.py --name ocr_v1_mild --augment mild --epochs 30
python train_ocr.py --name ocr_v1_strong --augment strong --epochs 10 --lr 3e-4 --init runs/ocr_v1_mild/best.pt
python train_ocr.py --eval-only --init weights/ocr_v1.pt    # 테스트만
```

`make_ocr_v1.py`가 하는 일:

- AI Hub OCR crop (Training + Validation 9만 장) 중 지원 형식만 사용: 일반 `12가3456`·`123가4567`, 지역명 `서울12가3456`·`서울4도9472`. 이륜차·건설기계 등은 제외
- 같은 번호는 최대 5장, **번호 단위로 train/val/test = 8:1:1** (AI Hub Validation 폴더는 Training과 번호가 겹쳐서 합친 뒤 다시 나눔)
- plate_v3로 번호판 crop (못 찾은 것 126장 제외) → 줄 검출 → 두 줄이면 펴기 → 높이 48로 저장

| | 장수 | 일반 1줄 | 일반 2줄 | 지역명 1줄 | 지역명 2줄 |
|---|---|---|---|---|---|
| train | 54,991 | 42,766 | 388 | 8,317 | 3,520 |
| val | 6,864 | 5,318 | 54 | 1,054 | 438 |
| test | 7,030 | 5,488 | 48 | 1,023 | 471 |

학습: 약한 증강 30 epoch(5분) → 강한 증강 10 epoch(2분), RTX 4090 기준. 처음부터 강한 증강을 쓰면 학습이 잘 안 된다 (팀원 실험 결과).

알려진 데이터 문제: 줄 검출이 두 줄 번호판을 한 줄로 보거나(펴지지 않음), 번호판 아래 작은 문구를 둘째 줄로 잡는 경우가 일부 있다.
