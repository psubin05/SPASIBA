# 입차 번호 저장 → QR 기반 차량 찾기

> 통합 이전 독립 시연 기록이다. 현재 server/matching은 임시 어댑터 대신 실제
> 수인 매칭 서비스를 사용한다. 실행 방법은 [통합 문서](integration_matching.md)를 따른다.

## 사용자 흐름

1. 차단기 카메라가 차량번호를 읽는다.
2. 인식된 번호를 POST /entries로 등록해 새로운 입차 세션을 만든다.
3. 주차면 카메라가 slot_id와 번호판 관측을 보낸다.
4. 수신·매칭 파트가 입차 세션과 주차면을 연결한다.
5. 이용자가 QR을 스캔한다. QR URL의 location_id는 보행 출발 위치다.
6. 차량번호 검색 결과가 CONFIRMED이면 해당 slot_id로 /route를 요청한다.
7. 위치 확인 중(PENDING)이면 경로를 생성하지 않고 기다린다. 출차 후 검색은 404다.

입차 때 번호를 저장하는 것만으로는 어느 주차면에 주차했는지 알 수 없다.
주차면 관측·매칭 과정이 있어야 QR에서 내 차까지 안내할 수 있다.

## 로컬 시연 실행

```powershell
.\.venv\Scripts\python.exe -m uvicorn server.demo_app:app --host 127.0.0.1 --port 8000
```

http://127.0.0.1:8000/simulator 접속.

1. 운영자 영역의 `차단기 인식 결과 저장`을 누른다. 차량번호를 저장한다.
2. 이용자 영역에서 같은 번호를 검색하면 `위치 확인 중`이 나온다.
3. 운영자 영역의 주차면을 선택하고 `주차면 관측 전송`을 누른다.
4. `이 QR 위치로 접속하는 링크`를 열면 location_id가 유지된 새 접속을 재현한다.
5. 이용자 영역에서 같은 번호를 검색하면 확정된 칸으로 3D 경로가 나온다.
6. 이동 재생으로 안내를 확인한다.
7. 운영자 영역의 차단기 번호 입력값을 확인하고 출차 처리한다. 다시 검색하면 기록 없음이다.

입력 예시는 가상의 `12가3456`이다. SQLite는 `.local/demo.sqlite3`에 저장되며
앱을 재시작해도 남는다. 다른 시연 DB를 쓰려면 SPASIBA_DEMO_DB 환경변수를 설정한다.
이 폴더는 gitignore에 포함되어 있다.

QR 링크는 `/simulator?location_id=QR-B2-ENT1` 형식이다. 현재는 링크로 QR 접속을
재현하며 스캔할 QR 이미지 생성은 아직 제공하지 않는다. localhost 링크는 현재 PC용이다.
휴대폰 접속용 QR은 시연 서버의 실제 접속 주소가 정해진 뒤 그 주소로 생성해야 한다.

## 실제 구현과의 경계

`server.app:app`은 지도·경로만 제공한다.
`server.demo_app:app`에서만 별도의 로컬 시연 어댑터를 켠다.
수인 담당 파일을 덮어쓰지 않고 `demo_parking.py`에 임시 어댑터를 분리했다.

어댑터는 entry/exit/last-location 계약에 맞춘 최소 동작, EXACT/고유 EDIT1 매칭,
중복 이벤트 제거, 잘못된 등록 관계 검출, 늦게 도착한 이전 관측 보호를 제공한다.
`POST /simulator/events`는 MQTT 관측을 대신하는 로컬 전용 입력이다.
이는 server_interface의 정식 MQTT/REST 엔드포인트를 바꾼 것이 아니다.

실제 촬영·OCR·차단기 제어·MQTT·PostgreSQL·crop 요청·120초 관리자 검토 큐·배정 이력·
세션 없는 이벤트 기반 조회 fallback은 이 로컬 어댑터 범위에 없다.
실제 서비스는 수인의 세션·이벤트·매칭 구현으로 교체하고 같은 프런트 요청을 사용한다.
시연 어댑터는 로컬 실행용이며 외부 서비스 배포용이 아니다.

우드락 치수·SVG 저장은 보류된 제작 도구로 접어두었다. 시연의 기본 동선은
차량번호 검색이며, 주차면 직접 선택으로 경로를 그리는 기능은 지도 단독 검증용이다.
