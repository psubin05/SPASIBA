## 1. 파이프라인에서 맡는 일

```
[Pi]  카메라 → ① 번호판 검출(YOLO11n) → ② 한 줄/두 줄 판단 → ③ 줄 검출(PP-OCR det) → ④ 글자 인식(PP-OCR rec, CTC) → 확률표 + slot_id 전송
               ^^^^^^^^^^^^^^^^^^^^^^^
               이 문서의 범위
[서버] ⑤ 버퍼 매칭 → 애매하면 Pi에 crop 재요청 → ⑥ 2차 판독(AI Hub CRAFT+STR) → DB 저장 / "미확인 차량"
```

①은 카메라 화면 전체에서 **번호판 영역만 박스 하나로** 잘라 ②~④로 넘긴다. OCR만 있으면 될 것 같지만 검출기를 따로 두는 이유는 두 가지다.

| 이유 | 설명 |
|---|---|
| **번호판이 아닌 글자 거르기** | 차 로고·모델명(`GRANDEUR`), 매장 간판(`DEUTSCH AUTOWORLD`), 택시 표시등, 광고 문구를 OCR이 같이 읽는다. 번호판 박스 안에서만 읽으면 이 문제가 사라진다. |
| **두 줄 번호판을 한 덩어리로 묶기** | 초록 구형·화물차 번호판은 두 줄이다. 줄 단위로만 검출하면 위아래 줄이 같은 번호판인지 알 수 없다. 검출기가 두 줄 전체를 **박스 하나**로 잡고, ③이 그 안에서 줄 수를 세어 ②를 판단한다. |

그래서 ①에 필요한 조건은 다음과 같다.

- 번호판에 **딱 맞는 박스 하나** (두 줄도 하나, 범퍼 여백 최소)
- 번호판 외 글자 영역은 잡지 않음
- **라즈베리파이 4에서 실시간에 가깝게** → YOLO11n, NCNN 변환 예정
- 글자를 읽을 필요는 없음 (읽기는 ③④의 일)

> 참고: 검출기의 일은 두 가지다. 이 문서는 **일 1 (실제 카메라 화면에서 번호판 찾기)** 이다.
> **일 2 (AI Hub OCR crop 안에서 번호판만 다시 자르기)** 는 기존 `plate_ft_rf_v1`으로 해결하며 바뀐 것 없다.

## 2. 왜 v2가 필요한가 — 지금까지의 시도

| 모델 | 학습 데이터 | 결과 | 원인 |
|---|---|---|---|
| `plate_blur_v1` | AI Hub 원본 프레임 3.2만 장 (번호판 **블러**) | 블러 검증 mAP50 0.994, **선명한 번호판 0/48** | "모자이크 사각형"을 번호판으로 배움 |
| `plate_ft_rf_v1` | blur_v1 + Roboflow korea plate (번호판 **crop**) 파인튜닝 | crop 안에서는 잘 찾음 (일 2용으로 사용) | 차 맥락이 없는 데이터라 일 1에는 부적합 |
| `plate_mix_v1`, `v1-2` | 블러 3.2만 + Roboflow crop 섞기 | 웹에서 모은 실제 사진 21장에서 대부분 못 찾음 | 아래 표 |

블러 데이터와 crop 데이터를 섞어도 안 되는 이유:

| 데이터 | 차 맥락 | 선명한 번호판 |
|---|---|---|
| AI Hub 원본 (블러) | ✅ | ❌ 모자이크 |
| Roboflow / AI Hub OCR crop | ❌ 번호판이 화면을 채움 | ✅ |
| **실제로 필요한 것** | ✅ | ✅ |

모델은 "차 안의 번호판 = 모자이크", "선명한 번호판 = 화면을 꽉 채우는 것"을 배운다. **"차 안에 있는 선명한 번호판"** 이라는 조합이 학습 데이터에 한 장도 없었다. 합성(블러 자리에 선명한 번호판 붙이기)은 합성 티와 손이 많이 가는 점 때문에 보류했다.

v2는 **처음부터 "차 + 선명한 번호판"이 함께 있는 공개 데이터**로 학습한다.

## 8. v3 — AI Hub 두 줄·초록 번호판 추가 (`plate_v3`)

### 8.1 왜

`plate_v2`는 실제 사진 21장 중 20장을 찾았지만, 놓친 1장이 **초록 구형 두 줄 번호판**(`서울4 도9472`)이었다. Roboflow 데이터에는 차에 붙은 초록 번호판이 거의 없다. 노란 번호판은 rf_alpr에 많다.

### 8.2 데이터

| 이름 | 위치 | 내용 |
|---|---|---|
| `aihub_rare` | `data/aihub_rare/` | AI Hub OCR crop(Training) 49,320장을 PP-OCR 줄 검출 + 색으로 걸러낸 후보 3,688장 (두 줄 3,552 / 초록 96 / 옛 형식 40) |
| `aihub_sel_1000` | `data/aihub_sel_1000/` | 위 후보에서 고른 1,000장 (train 900 / val 100) |
| `test_green` | `data/test_green/` | 웹에서 모은 초록 번호판 사진 26장, 직접 라벨링한 박스 55개. **평가 전용** |
| `plate_v3` | `data/plate_v3/data.yaml` | `plate_v2` + `aihub_sel_1000` (폴더 목록만 묶음) |

`aihub_sel_1000` 만드는 법:

- 제외: 시·군 이름이 들어간 번호(`경기부천아0467`) — 대부분 이륜차·건설기계 (결정 3)
- 같은 번호는 1장
- AI Hub OCR 라벨에는 **박스가 없어서** 자동 생성: `plate_ft_rf_v1`과 `plate_v2`의 확신도 1등 박스가 IoU ≥ 0.7로 일치할 때만 채택 (박스는 ft_rf_v1 것). 2,278장 중 **2,129장(93%) 일치**
- 초록 후보는 채택된 것 전부(229장), 나머지 771장은 무작위
- 학습 데이터 중 crop 비율은 약 11% (차 맥락 없는 crop이 많으면 "번호판 = 화면을 채우는 것"을 배울 위험)

### 8.3 학습

`plate_v2`와 같은 조건 (yolo11n COCO, 640, 50 epoch, 결정 8 증강). 학습 7,779 + 900장, 약 15분.

### 8.4 결과

**plate_v2 검증 세트 (출처별)** — 원래 성능 유지, 조금씩 개선

| 출처 | v2 Recall | v3 Recall | v2 mAP50-95 | v3 mAP50-95 |
|---|---|---|---|---|
| rf_alpr | 0.961 | 0.969 | 0.795 | 0.788 |
| rf_lp_detect | 0.954 | 0.960 | 0.799 | 0.809 |
| rf_korean_license | 0.806 | 0.833 | 0.565 | 0.572 |
| rf_plate_night | 1.000 | 1.000 | 0.800 | 0.802 |
| AI Hub val 100 | 0.980 | 1.000 | 0.706 | 0.851 |

**test_green (초록 26장, 폭 30px 이상 번호판 30개)**

| | v2 | v3 |
|---|---|---|
| IoU ≥ 0.5 | 26 | 24 |
| 번호판을 90% 이상 덮는 박스 있음 | **30 / 30** | **30 / 30** |
| 박스 넓이 / 정답 넓이 (중앙값) | 1.7배 | 1.6배 |

- IoU 기준으로 "놓친" 경우는 실제로는 번호판을 찾았지만 **거치 홈까지 넓게 잡은 것**이다. 두 줄을 모두 덮으므로 OCR로 넘기는 데는 문제없다.
- 폭 30px 미만의 아주 작은 배경 번호판(25개)은 두 모델 모두 대부분 놓친다 (v2 6개, v3 5개). 가까운 거리의 주차장 카메라에서는 영향이 작다.

**실제 사진 21장의 image5 (`서울4 도9472`)**: v2는 conf 0.1에서도 못 찾음 → **v3는 0.73으로 찾음**
