# 실물 모형과 시뮬레이터 연결

## 현재 배치

사용자 결정: A열·B열별 기존 카메라 배치를 유지한다.
양쪽 각 4면, 가운데 통로, 왼쪽 QR 출발점, A/B 카메라 각 1대의 임시안이다.
이 모형은 아직 제작되지 않았다. `map/b2.json`이 API와 시뮬레이터의 공통 원본이다.

`nodes/edges`는 보행 경로, `slots[].polygon`은 바닥 주차면 경계,
`demo_layout`은 바닥·벽·카메라 거치점의 표현용 정보다.
`roi`는 실물 카메라 영상에서 보정해야 하므로 현재 null을 유지한다.

## 제작 순서

1. 사용할 장난감 차의 가로·세로와 번호판 부착 위치를 측정한다.
2. 시뮬레이터에서 모형 가로 크기를 조절해 주차칸에 자동차가 들어가는지 검토한다.
3. 카메라 한 대와 차량 한 대로 촬영 각도·번호판 크기·조명 조건을 먼저 확인한다.
4. 배치가 정해지면 SVG를 저장하고, 실제 치수를 확인해 우드락에 옮긴다.
5. 칸에는 A-01…B-04를 표기하고 서버의 slot_id와 연결한다.
6. 실물 위치를 측정해 노드·간선·polygon·카메라 위치를 원본 JSON에 반영한다.
7. 실물 영상으로 각 주차면 ROI를 정해 camera_id/slot_id 등록 정보와 맞춘다.

기본 화면의 110×40cm는 임시안이다. 추천 제작 규격이나 실측값이 아니다.
기본 비율에서는 주차칸 12.5×10cm, 통로 10cm로 표시된다.
화면의 가로 크기 변경은 제작 cm 환산과 SVG 크기에만 적용된다.
실제 차량 서비스의 경로 응답 `distance_m`는 가상 지도 m 단위로 유지된다.
제작 크기를 바꿨다고 서버 경로 거리를 장난감 모형의 실측 거리로 표시하지 않는다.
SVG에는 보드 치수가 있으나 프린터의 페이지 맞춤·축소 여부를 따로 확인해야 한다.

## 시연 흐름

현재 독립 시뮬레이션: 주차면 선택 → 경로 요청 → 3D 경로/안내 표시 → 이동 재생.
체크박스 차량은 배치를 검토하기 위한 표시이며 서버의 실제 점유 정보가 아니다.
경로를 보고 싶은 빈 주차면도 독립 시뮬레이션에서는 선택할 수 있다.

통합 시연: 가상 입차 등록 → Pi가 실제 모형 차량 인식 → 수인 서버가 매칭 →
Web이 차량 위치 검색 → CONFIRMED의 slot_id로 경로 요청 → 같은 주차면으로 안내.
PENDING이면 위치 확인 중을 표시하며 칸까지의 경로 요청은 보류한다.

실제 인식, 카메라 촬영 범위, OCR 정확도, 실시간 점유 연동은 현재 3D 재생에 포함되지 않는다.
