# 팀 결정 안건

## 통합 브랜치에서 적용한 규칙

- v0.4 카메라 토픽과 식별자를 사용한다. 담당 칸은 `parking_slot.camera_id`로 등록한다.
- 시연에서만 OCR 합의 발행을 켠다. 일반 Pi 설정의 기본값은 보류다.
- 첫 시연의 기본 경로는 Crop 없이 동작한다. 별도 검증에서는 Pi와 서버 양쪽의 Crop을 활성화한다.
- 동일 차량의 동일 칸 재입차는 1차 시연 범위에서 제외한다. 출차 이후 다시 같은 칸을 읽으면 Pi의 마지막 발행 번호가 남아 보류 상태가 되는 동작을 테스트로 재현했다.

## 합의할 사항

| 안건 | 팀에서 정할 내용 |
| --- | --- |
| 정차 판단 | 체류·속도·센서 등 입력과 안정화 조건. OCR 합의는 시연에 사용한다. |
| 빈 주차면 판단 | 센서나 운영자의 명시적 EMPTY 판정 조건. 합의 전에는 경과 시간이나 인식 끊김으로 EMPTY를 확정하지 않는다. |
| 동일 칸 재입차 초기화 | ① Pi에서 명시적으로 EMPTY를 기록 후 OCCUPIED로 복귀 ② 서버에서 초기화 요청을 보내는 방식 ③ 실제 점유 판정 도입. ②를 선택한다면 출차와 실제 빈 상태의 차이, 인증·기대 이전 이벤트 ID·멱등성·확인 응답을 먼저 정의한다. |
| Crop 사용·보관 | 기본 사용 여부, TTL과 서버 저장 기간, 접근권한, 확인 완료나 출차 시 삭제 책임. |
| Crop 실패 | 사진 없음·만료·ID 불일치의 명시적 오류 응답 및 재요청 정책. 현재는 무응답이며 확인 항목은 사진 없이 유지된다. |
| 카메라 배치 | 실제 설치 위치와 담당 주차면, ROI 및 해상도. 통합 샘플의 `B2-B-03` 교차 구역 매핑은 검증용이다. |
| 지도 관리 | 원본 갱신 주체와 배포 경로. 지도 담당자는 `map/b2.json`의 카메라 ID와 각 칸의 참조를 함께 갱신하고 `tools/export_map_sql.py`로 SQL을 재생성한다. 설치 구역과 담당 칸을 분리하고 `roi`(카메라 픽셀)와 `polygon`(웹 지도)을 구분한다. |
| 시연 환경 | LAN 서버 또는 클라우드의 실제 시연 환경, 주소·CA 발급 및 운영 백업. |
| 관리자 확인 | 목록·사진·해결 API 공개 범위와 인증, 자동 확정 검토, 사진 삭제·감사 정책. 현재 REST는 501이다. |
| 기존 데이터 전환 | 가동 중인 Pi와 DB의 실제 구형 ID→v0.4 ID 매핑, 기존 Outbox 처리, 새 MQTT 계정과 전환 시점. |
